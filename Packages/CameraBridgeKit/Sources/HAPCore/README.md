# HAPCore

HAP building blocks with no networking: TLV8, pairing cryptography, setup codes/payloads, identities.
Depends on BridgeSupport, swift-crypto `Crypto` (re-exports CryptoKit on macOS; never `import CryptoKit`) and
attaswift/BigInt (MIT).

## Public entry points

- `TLV8` (`Item`, `encode`, `decode`, `splitList`), `TLV8Error`, `TLVBuilder`, `TLVReader`.
- `HAPCrypto`: `hkdfSHA512` (String or Data salt), `nonce(label:)`, `nonce(counter:)`, `chachaSeal`, `chachaOpen`,
  `sha256` (swift-crypto; HAP's `c#` and HAPCamera's recording-configuration hash).
- `SRPServer` (accessory) / `SRPClient` (test controllers), `SRPError`.
- `HAPLongTermKey` (Ed25519), `DeviceID`, `SetupCode`, `AccessoryCategory`, `SetupPayload` (`uri`, `setupHash`,
  `randomSetupID`).

## Additions beyond the contract

`TLVBuilder.addSeparator(type:)` (camera TLVs separate list entries with `00 00`; `addSeparator()` writes
`FF 00`), `X25519KeyPair` (pair-verify ephemeral keys + shared secret), `HAPCryptoError`, `HAPCrypto.sha256(_:)`
(replaced HAP's hand-written `HAPSHA256`, W4 review).

## Invariants

- TLV8: values > 255 bytes are split into 255-byte same-type fragments. `decode` merges an item into the
  previous one only if the previous item had length 255 and the same type; separators are returned as items.
- `TLVReader.uint16LE/uint32LE/uint64LE` accept the shorter little-endian encodings (1/2/4/8 bytes).
- ChaCha20-Poly1305: 32-byte key, 12-byte nonce, output `ciphertext ‖ tag(16)`; any failure →
  `HAPCryptoError.authenticationFailed`. HAP nonces are `00000000 ‖ label(8)` or `00000000 ‖ LE64(counter)`.
- SRP-6a exactly per research brief §3.2: RFC 5054 3072-bit group, g = 5, SHA-512, k = H(N ‖ PAD(g)),
  u = H(PAD(A) ‖ PAD(B)), x = H(s ‖ H(I ‖ ":" ‖ P)), K = H(PAD(S)),
  M1 = H(H(N) ⊕ H(g) ‖ H(I) ‖ s ‖ A ‖ B ‖ K), M2 = H(A ‖ M1 ‖ K). The server hashes A as received.
  P is the setup code *with dashes* (`SetupCode.formatted`). Salt 16 bytes, private values 32 bytes.
- Modular exponentiation uses `MontgomeryContext` (internal, fixed 48×64-bit limbs) because BigInt compiled at
  -Onone (Debug/`swift test`) took tens of seconds per exchange. It is side-channel hardened (best effort): fixed
  4-bit windows over every exponent word, masked table scan, masked final subtraction; the server's k·v + g^b
  and A·v^u products also go through it. BigInt remains for public-value arithmetic (u, A mod N checks).
- `SetupCode.isTrivial`: all-same digits or any consecutive ascending/descending run (superset of the contract's
  12345678/87654321 examples, per research brief §3.3 "ascending/descending"). `random()` never returns one.
- Setup URI: low32 = code | 1<<28 | (category & 1)<<31, high32 = category >> 1, base-36 uppercase, padded to 9.
  `Identity.swift` carries the HAP-NodeJS attribution header (setup URI / `sh` algorithms, via brief §3.3).
- Ed25519 signatures from CryptoKit (via `Crypto`) are randomized: test by verifying, never by comparing bytes.
