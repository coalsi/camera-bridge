# Contract changes

Deviations from `docs/superpowers/plans/2026-09-30-camerabridge-contracts.md` and from the plan's fixed layout.
Record every rename, removal, signature or meaning change here (date, module, change, reason). Non-breaking
additions are listed in each module's README under "Additions beyond the contract".
`Packages/CameraBridgeKit/Tests/IntegrationTests/ContractSurface.swift` type-checks the whole contract surface;
update it together with this table.

The Status cell starts with one of these terms (`Tests/PortabilityTests/DocsConsistencyTests` accepts no other):
- **pending**: the row changes the contract itself (a rename, removal or signature change, a new requirement without a
  default on a contract protocol, or the meaning of contract text, the portability rule included) and waits for
  orchestrator approval. Until the orchestrator approves it, every line of contract text the row quotes carries a
  "pending" note naming this file.
- **approved** / **resolved**: the orchestrator approved the change, or settled it another way.
- Every other status says how the row stays within the contract (plan layout, scope or wording): **additive** (new API
  only; a requirement added to a contract protocol has a default implementation, so conformers written to the contract
  still compile), **no API change**, **doc sync**, **implemented**, **superseded**, **within** (the contract, plan, spec
  or portability rule), **matches the contract**, **superset of the contract**, **stricter than plan**.
