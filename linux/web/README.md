# Camera Bridge web interface

The page `camerabridged` serves at `http://camera-bridge.local`. Plain HTML, CSS and ES modules: no build step, no framework, no CDN,
no external fonts. Dark by default and light with the system (`prefers-color-scheme`), bridge red `#9E2B20` with cream text on
fills and light red `#E06A5A` for text on dark, on dark neutral; the logo is the Golden Gate seen through a lens
(`docs/brand/BRAND.md`). Phone and desktop (a tab bar at the bottom on a phone), keyboard and screen reader friendly (landmarks,
labels, visible focus, live regions, native dialogs, reduced motion).

```
index.html            the shell; one module script
style.css             tokens (colours, spacing), layout, components
js/app.js             boot (first run, sign in, signed in), the hash router, the shell
js/api.js             fetch with the session cookie and the anti-forgery token
js/store.js           cameras and bridge state, kept current by /api/v1/events; which plugins are on (`pluginOn`, read from `GET plugins` at start-up and whenever the Plugins page loads)
js/dom.js             h(), modal dialogs, toasts (everything is built with the DOM API, never innerHTML)
js/screens/           auth, cameras (the Cameras list, #/cameras), nvr (the Monitor: the home page's wall with the recordings), wall-events (its notices), add (the wizard), camera, night-vision (Auto, Night, Day and the IR lights: a card on the camera page, buttons beside or under the Monitor's pan/tilt pad), ai-settings (Settings' AI descriptions card, the words and banners the camera page's AI descriptions card shares; `#/settings/ai`), sky-model, sky-card, sky-setup, sky-log, sky-grid, sky-player and sky-player-model (Sky Watcher, a plugin: its words, the camera page's card and the Setup panel, the sky log at `#/sky`, its grid and its clip player; see "Sky Watcher" below), plugins (Plugins: Wyze, eufy and Sky Watcher, each with a switch), pairing, settings, logs, system, banners
js/nvr/               recording and playback (see "Recording and playback" below)
js/live/              live video and the picture tools: mux.js, pan-tilt.js, zoom.js and straighten.js (Straighten the picture: the correction's formula, copied from MediaCore's `PictureCorrection`, and a `<video>` or `<img>` drawn straightened on a canvas over it, with WebGL or else in 2D; the camera page's card is in screens/camera.js)
nvr-record.css, nvr-watch.css, nvr-grid.css    styles of the recording screens (style.css is not edited for them)
sky.css               Sky Watcher's card, page, grid and clip player (every class starts with sky-); linked from index.html after monitor.css, whose dark colours and transport rules the clip player shares (`:is(.monitor, .sky-player)`)
mark.svg, mark-small.svg, site.webmanifest    the logo (mark-small.svg at 32 px and below: favicon, sidebar), the manifest
```

The Content-Security-Policy the server sends allows only these files and media played from a `blob:` URL (`media-src 'self' blob:`): no
inline scripts or styles, so new code must not use `style="…"` attributes, `innerHTML` or `eval` (set `el.style.x` from script, which the
policy allows).

## Recording and playback

Recording, storage settings, banners and playback are plain ES modules under `js/nvr/` and `js/screens/`, loaded on demand: `app.js` wraps the new screens in `lazy()`, and `js/nvr/lite.js` is the only static import, so a broken recording module cannot blank the sign-in page. Times in these modules are epoch milliseconds from the box's clock unless a name says seconds (`startSec`, `bufferSeconds`).

| Files | What |
|---|---|
| `js/nvr/lite.js`, `ui.js`, `record.js`, `storage.js`, `storage-info.js` | The Record switch (camera card, camera page, watch screen), the first-time "Where should recordings be stored?" dialog, Settings > Recording (its numbers and sentences are plain functions in `storage-info.js`) and the keyframe note. `lite.js` loads `ui.js` on demand |
| `js/nvr/fetcher.js`, `catalog.js`, `clock.js`, `planner.js`, `cell.js`, `surface.js`, `session.js` | The player: a page-wide request scheduler (3 byte fetches and 1 JSON request at a time), the catalog and server-clock poll, the playback clock, the pure rules for what to fetch, one tile (`cell.js`, with one MediaSource in `surface.js`) and the shared playhead for one to nine tiles (`session.js`) |
| `js/nvr/transport.js` | The recordings' transport the Monitor and Sky Watcher's clip player share: one picture back, Play or Pause, one picture forward, the readout, the speed menu in its four groups and the keyboard help, drawn from the grid controller's `transport` |
| `js/nvr/speed.js`, `frames.js`, `clip-range.js`, `clip.js` | Playback speeds in four groups (Slow ¼× ½×, Normal 1×, Fast 2× 4× 8× by `playbackRate`, Time-lapse 30× to 300×, which the session plays by asking every cell for the key picture at the clock every 500 ms through the page's key-picture budget instead of playing video); sound at 1× only. A picture's length read from the fragments' `trun`/`tfhd`/`trex` and where a step of one picture lands (`frames.js`). The clip's range: a red band on the timeline with a handle at each end (`view.js` `setClipRange`), by default the chosen length before the playhead, inside the footage, at most 2 hours (`clip-range.js`); the clip bar's lengths (10 s to 15 min) and its Time-lapse choice (`speed=` on the clip route) |
| `js/nvr/timeline/viewport.js`, `ticks.js`, `activity.js`, `model.js`, `draw.js`, `scrub.js`, `keys.js`, `view.js` | The timeline: zoom and pan, calendar-aligned ticks, the activity wave and its scale, the model that follows the live edge (the preset is remembered in `cb.nvr.zoom`), the canvas painter, the pointer handling, the keyboard map and the control that ties them together |
| `js/screens/watch.js`, `watch-state.js`, `preview.js`, `optimize-dialog.js` | The watch screen and its rules (`watch-state.js`, no DOM), the snapshot picture used when Record is off, and the smart-codec dialog |
| `js/screens/nvr.js`, `nvr-model.js`, `nvr-controller.js` | The NVR page: a grid of tiles on one playhead (9 on a page by default, 2 on a phone; the Per page control, `?tiles=` or `cb.nvr.tiles` change it, 1 to 16), its rules and its controller (no DOM) |
| `js/screens/nvr.js` + `monitor.css`, `js/screens/wall-events.js`, `js/live/mux.js` | The Monitor (`#/`, also `#/monitor` and `#/nvr`): every camera on a black wall with the recordings' controls (Live at the live edge; while looking back the frame steps on either side of Play/Pause, the speed menu, a keyboard help and Live at the right end of the row; Pause holds: a drag, a jump, an event, a step or a new speed leave it paused, only Play or Live plays (`session.holding`, `showAt`, `stepFrame`); ← → step a picture while paused and seek a second while playing, Shift + ← → a minute, Alt + ← → ten seconds; timeline, presets, clips, grid size or the mosaic's cameras across, pages, dragging a tile onto another's place or Alt + arrow keys to put the cameras in order: `js/camera-order.js`, `js/screens/nvr-reorder.js`), live video for every tile whenever the wall is live (Smooth or Full quality), the date and time on every picture, notices, an events list (the archive's events for the timeline's range, `GET nvr/events`, with the live ones, and an AI service's sentence under an event it described; `wall-events-model.js` has the rules) and sound for motion, detections and doorbell rings; Full screen fills the display |
| `js/stamp.js`, `js/theme.js`, `theme-boot.js`, `js/power.js` | The date-and-time written on every picture; the Auto / Light / Dark appearance; Power off |
| `nvr-record.css`, `nvr-watch.css`, `nvr-grid.css` | Styles of the recording screens; `style.css` is not edited for them |
| `js/screens/archive-drive-card.js` | The archive drive (where older recordings move when the box's own disk fills, instead of being deleted): the System page's "Archive drive" card (the drives from `GET system/archive-drives`, "Use as archive" for an archive drive, "Use as archive…" with the typed `ERASE ALL DATA ON <disk>` for another, "Stop using the archive drive…"; its state, used and free, how far back it goes and what moves now from `GET nvr/storage`'s `archive`), and the words the Recording card in Settings shows under the recordings drive's numbers (`describeArchive`). It is not NVR code: it loads with the System page. A stretch on an archive drive that is not connected is a quiet band on the timeline that says "On the archive drive (not connected)" (`nvr/activity`'s `away`), and a tile or the watch screen there says so (a plan's `reason: "archiveAway"`) |

Recorded video is fetched with `getBytes()` in `js/api.js` (the only place that calls `fetch`) and played through Media Source Extensions: a `blob:` media source is why the Content-Security-Policy has `media-src 'self' blob:`. Nothing in these modules uses WebCodecs, a worker or WebAssembly. `docs/linux/ARCHITECTURE.md` ("Recordings in the browser") explains the flow.


## Sky Watcher

A camera that looks at the sky can be watched for planes, satellites, meteors, bugs, birds and whatever is left over. The name in the page is **Sky Watcher** everywhere (the card, the menu item, the page's title); the settings and routes keep the code's name, `skyDetector`. All of it is vanilla JS in `js/screens/`, with `h()` and `replace()` from `dom.js`, the tokens of `style.css` in both themes and no inline styles.

**Sky Watcher is a plugin**, the third on the Plugins page (`#/plugins`, after Wyze and eufy), with the same switch, **off by default**. Its entry has one sentence of what it does and an **Open** button to `#/sky`; it has no account, sign-in or sync, so no page of its own under `#/plugins/`. The page learns which plugins are on from `GET plugins` (`store.js`: `loadPlugins` at start-up, `setPlugins` whenever the Plugins page reads the list, `pluginOn('sky')`):

| | Plugin off | Plugin on |
|---|---|---|
| Left menu and phone tab bar | no **Sky Watcher** item | the item, right after Notifications, all the time (not only once a camera has it on) |
| A camera's page | no Sky Watcher card | the card, after the AI descriptions card, on every camera |
| `#/sky` | "Sky Watcher is off", with a button to Plugins; nothing is asked of the bridge | the Setup panel at the top, then the log; with no camera on yet, "Turn on Sky Watcher in a camera's settings" with a link to each camera's page (or to add one) |
| `PATCH cameras/:id {skyDetector: {enabled: true}}` | 400, field `plugins.sky`, "Turn on Sky Watcher in Plugins first." (the card shows it with a link to Plugins) | as before |

Switching it off keeps every camera's saved settings, so switching it on again brings the same cameras back. A switch changed in another browser shows here the next time the page is loaded or the Plugins page is opened (the bridge sends no event for plugins).

| File | What |
|---|---|
| `js/screens/sky-model.js` | Pure: no document, no requests. Every sentence (`SKY_TEXT`), direction ("low in the northwest, 8° up"), speed ("about 6× faster across the sky than planes at that height": never a real speed), blinking, shape, the summary, the conditions line ("☁︎ clear until 3 AM; sky not visible 3–5 AM"), the aim by lens, the strip's dots and hour marks, the grid's kind chips (`GRID_KINDS`: planes with the probable ones, satellites with their flares, bugs and birds together, and the person's corrections), filters (`matchesFilters`, `chipCounts`), orders (`sortEntries`: newest or oldest first, the longest, the fastest across the sky by `measures.speed` with those of none last; `defaultSort`: the newest first while the night is still going, else the oldest), the box's clock hours (`hourGroups`, `hourStart`), a card's words (`kindWord`, `cardLine`, `durationShort`) and the address's part for them (`readGridQuery`, `gridQuery`), a path in picture coordinates, a still's close-up (`closeUpRect`: the path's box padded by half its size, at least 160 × 90 of the still's pixels, 16:9, inside the picture; none for a light that crossed more of the sky than that), the box's thumbnail of it (`THUMB_WIDTH`, 480; `thumbRect`: the close-up in whole pixels, which the box's Swift copy cuts to the pixel, tested against it case by case through `linux/web-tests/support/sky-closeup-vectors.mjs`; `thumbGeometry`: what a card's picture is, from its size once it has arrived, the close-up the box cut, the whole picture at some size, or neither), the Watch and clip addresses, and `SKY_ROUTE` |

| `js/screens/plugins.js` | The Plugins page: a card for each plugin the bridge lists, with its switch (`PATCH plugins/<id>`) and an **Open** button (`#/plugins/<id>`, or `#/sky` for Sky Watcher) |

What the page reads from the bridge (Task 5's API; `linux/web-dev/lib/sky.mjs` fakes it with a made-up night): `GET sky/cameras/:id/night?date=&view=` (`camera, night, view, from, to, serverTime, entries[], conditions[], counts, aim, learning, capped[], picture`; an entry has `display` and `watch`; `picture` is `{width, height}`, how big the night's pictures are, or null), `GET sky/cameras/:id/entries/:eid/still?night=[&size=thumb]` (the original picture, or with `size=thumb` the small one the grid's cards use; used as an `<img>`; the clip player keeps the original), `POST sky/cameras/:id/entries/:eid/correction {night, label}`, `POST sky/feeds/find`, `GET`/`PATCH settings` (`sky.location`, `sky.flightFeedURL`, `sky.aiDailyLimit`), `GET plugins` and `PATCH plugins/sky {enabled}` (the plugin's switch), `PATCH cameras/:id {skyDetector}` and, on each camera, `skyDetector` and `status.sky` (`running, stream, analysisWidth, picturesPerSecond, aim, learning, problem`). Times are epoch milliseconds from the box's clock, said in the bridge's time zone. Past the brief: `skyDetector.lensLayout` (`single` or `dual`), which the card sends and reads back (a picture 2 to 1 or wider is two lenses until it says otherwise).

Copy rules: no sentence says a real size, distance or speed of a light (nothing in km/h, mph, metres, feet or miles); a flight's own altitude is the feed's word and is shown as the bridge sends it ("TEST123 · 35,000 ft"). The explained entries are never built until their group is opened, so a night with hundreds of satellites stays quick. A correction changes the page in place (the entry stays where it is, and the counts and the strip follow it); nothing is loaded again.

## Run it on a Mac

```
cd Packages/CameraBridgeKit
swift run camerabridged --dev --data-dir /tmp/cb-dev --fake-discovery
open http://127.0.0.1:8080
```

`--dev` keeps the engine on loopback with nothing advertised and the HomeKit ports from 38100, so it never disturbs the Camera Bridge
app. The Add Camera page can add the demo camera (a test pattern with motion every minute) and `--fake-discovery` shows three
sample cameras on documentation addresses. `--preview` serves the engine's fixed sample data instead (no camera runs).
`camerabridged` finds this directory itself when started from the repository (`--static-dir` overrides).

The image installs these files in `/usr/share/camera-bridge/web`.

## Tests and tools

`linux/web-tests/` holds the tests of the pure modules (Node 22 or later, no packages): from the repository root, `node --test 'linux/web-tests/*.test.mjs'` (the quotes matter). `linux/web-dev/` holds the development tools:

| File | What |
|---|---|
| `dev-archive-server.mjs` | A Node server that serves `linux/web` and answers the recording routes from fixture files, with the daemon's Content-Security-Policy; switches for the cases "no folder", "drive missing", "disk full" and "stalled" |
| `make-fixtures.sh` | Builds the fixture files with ffmpeg |
| `conformance.mjs <base-url>` | Signs in and checks the shape of every recording route against a dev server, a daemon on a Mac or a box (the password comes from the environment and is never printed) |
| `lint.mjs` | Rejects what the Content-Security-Policy forbids: `innerHTML`, `style="…"`, `eval`, `fetch` outside `api.js` and the like |
| `spike/` | The browser test pages for plain HTTP (secure context, Media Source Extensions) |
| `soak/` | The Node side of the soak and fault tests: scripted clients, the sampler, the analyzer and the file verifier (`Tools/nvr-soak/README.md` says how a run goes) |
| `t10-run.mjs`, `t10-drive.js`, `t10-checks.js`, `t10-open-at.js`, `t10-smoke/` | Checks of the Watch screen in a throwaway headless Chrome: `node linux/web-dev/t10-run.mjs <url> <file.js>` evaluates the files in the page, and the first lines of each file say what it does |

Both directories live outside `linux/web/` because the image copies that whole directory (`linux/os/build-image.sh`).

`linux/web-dev/README.md` describes the dev server's nine fake cameras and its scenarios, and `linux/web-tests/README.md` the tests; `sh linux/web-tests/run.sh` runs all of them and makes the fixture clips first (tests that need `ffmpeg` skip, with the reason, when it is missing).

Test recordings the way the box shows them. A page from `http://127.0.0.1` is a secure context, so browsers offer features there that they do not offer on `http://camera-bridge.local`, which is not one: print `window.isSecureContext` and `typeof VideoDecoder` to see the difference. To see what the box shows without opening your Mac to the network, give the loopback address a name that is not a secure context. Start the daemon for that name, and map the name to 127.0.0.1 inside one browser only (Chrome: `--host-resolver-rules="MAP nvr.test 127.0.0.1"`, with its own `--user-data-dir`):

```
cd Packages/CameraBridgeKit
swift run camerabridged --dev --data-dir /tmp/cb-nvr --port 8081 --fake-discovery --allowed-host nvr.test
```

Then open `http://nvr.test:8081` in that Chrome. `--dev` keeps the web interface on 127.0.0.1, so only this Mac can reach it, and the daemon advertises nothing and uses HomeKit ports from 38100, so it does not disturb the Camera Bridge app.

## Screenshots

Taken from the daemon on a Mac with the demo camera (a test pattern) and documentation addresses: `docs/linux/screenshots/` (cameras, add a camera, a camera, pairing, log, phone, system in light mode).

Notifications (2026-10-22): a notice is not a banner any more. `js/notifications.js` shows each new one once as a toast at the top right (6 s, a warning 10 s, held by the pointer or the keyboard focus, at most 3, a swipe or the close button puts it away) after asking the bridge (`POST notifications/shown`: the bridge hands each to one browser, so nothing comes back on a reload and the phone and the Mac agree; nothing is kept in the browser), and counts the unread ones for the menu's bell. `js/screens/notifications.js` is the Notifications page (`#/notifications`: the bridge's log, a filter by section, "Mark all as read"; opening it marks what it shows as read). `js/screens/banners.js` keeps only the bridge's own state (paused, starting, not running) as a slim line.
