# Camera Bridge web interface

The page `camerabridged` serves at `http://camera-bridge.local`. Plain HTML, CSS and ES modules: no build step, no framework, no CDN,
no external fonts. Dark by default and light with the system (`prefers-color-scheme`), bridge red `#9E2B20` with cream text on
fills and light red `#E06A5A` for text on dark, on dark neutral; the logo is the Golden Gate seen through a lens
(`docs/brand/BRAND.md`). Phone and desktop (a tab bar at the bottom on a phone), keyboard and screen reader friendly (landmarks,
labels, visible focus, live regions, native dialogs, reduced motion).

```
index.html            the shell; one module script
style.css             tokens (colours, spacing), layout, components
js/app.js             boot (first run, sign in, signed in; a bridge that does not answer is asked again after 5, 10, 20, then every 30 s), the hash router, the shell (on a phone a tab bar with More)
js/api.js             fetch with the session cookie and the anti-forgery token
js/store.js           cameras and bridge state, kept current by /api/v1/events (a stream silent for 40 s once the bridge sent a `ping` is opened again; each new stream's snapshot removes the cameras it no longer names; after a lost contact `GET system` tells whether the bridge was updated: "Camera Bridge was updated" with Reload); which plugins are on (`pluginOn`, read from `GET plugins` at start-up and whenever the Plugins page loads); the bridge's time zone (`bridgeZone`: `settings.timeZone`, the browser's until it is read), which every time on the page is said in
js/zone.js            times in a zone: the wall-clock fields of an instant, the first instant of a day, formatters kept per zone, the zone's short name, a typed date and time as an instant (the timeline's ticks use them too)
js/wall-mode.js       the wall display (the Monitor's switch, kept in this browser): the Monitor keeps the screen awake and hides its controls, and this browser claims no notification toasts
js/dom.js             h(), modal dialogs, toasts (everything is built with the DOM API, never innerHTML)
js/qr.js              QR codes drawn by the page (`encodeQR`, `qrPath`): a port of BridgeWeb/QRCode.swift (byte mode, levels L and M) extended to version 20, for a WireGuard device's configuration, which holds its private key and so is never sent anywhere to be drawn; QRCodeTests runs it with `node` and checks it gives the Swift encoder's codes and that Core Image reads the larger ones
js/screens/           auth, cameras (the Cameras list, #/cameras), nvr (the Monitor: the home page's wall with the recordings), wall-events (its notices), add (the wizard), camera (with its Pan, tilt and zoom card: the owner's switches for a camera whose control says it pans, tilts or zooms, shown only for what it said and saved with `PATCH cameras/:id {panTiltEnabled, zoomEnabled}`), night-vision (Auto, Night, Day and the IR lights: a card on the camera page, buttons beside or under the Monitor's pan/tilt pad), ai-settings (Settings' AI descriptions card, the words and banners the camera page's AI descriptions card shares; `#/settings/ai`), sky-model, sky-card, sky-setup, sky-log, sky-grid, sky-player and sky-player-model (Sky Watcher, a plugin: its words, the camera page's card and the Setup panel, the sky log at `#/sky`, its grid and its clip player; "Add a device" takes the 8 letters the device shows, `POST viewers/approve {code}`; Remove with `DELETE viewers/:id`, asked first; `#/pair/<code>`, the address in the QR code on the device (the phone's approve button opens it in Safari), opens Settings at the card with the code filled in and the keyboard on Add, and adds nothing by itself; the menu marks Settings for it, and Cameras still for `#/pair/sensors`) and Sign out; the Away from home section after it, from away-card (the box's own VPN for phones away from home: `GET away`, every 15 s while on, said state by state in plain words, with an eero's own router steps; the switch `POST away {on}`, and a toast when it turned the secure address on too; Remove with `DELETE away/devices/:id`, asked first; "Add a device with the WireGuard app", `POST away/devices {name}`, shows the configuration once as a QR code from qr.js and keeps nothing of it; a box without it, 503 `unavailable`, gets one line and no switch; `#/settings/away` opens Settings at the card); Monitoring from monitor-card under Apple Home and other systems: `monitorEnabled`, the token with Show, Copy and New token, and `GET /api/v1/monitor` with `Authorization: Bearer <token>`), logs, system (the secure address card's own switch: `POST system/secure-address/enabled`; while Away from home is on the box keeps it on, 409 `away_on`, and the card says the box's sentence under the switch), banners
```

The Content-Security-Policy the server sends allows only these files and media played from a `blob:` URL (`media-src 'self' blob:`): no
inline scripts or styles, so new code must not use `style="…"` attributes, `innerHTML` or `eval` (set `el.style.x` from script, which the
policy allows).

## Recording and playback

Recording, storage settings, banners and playback are plain ES modules under `js/nvr/` and `js/screens/`, loaded on demand: `app.js` wraps the new screens in `lazy()`, and `js/nvr/lite.js` is the only static import, so a broken recording module cannot blank the sign-in page. Times in these modules are epoch milliseconds from the box's clock unless a name says seconds (`startSec`, `bufferSeconds`), and they are said in the bridge's time zone (`store.js` `bridgeZone`), whichever zone the browser is in: the Monitor, the timeline, Events (its "Today" and its days), the Log, the clips (`tz=`) and storage.

## Sky Watcher

A camera that looks at the sky can be watched for planes, satellites, meteors, bugs, birds and whatever is left over. The name in the page is **Sky Watcher** everywhere (the card, the menu item, the page's title); the settings and routes keep the code's name, `skyDetector`. All of it is vanilla JS in `js/screens/`, with `h()` and `replace()` from `dom.js`, the tokens of `style.css` in both themes and no inline styles.

**Sky Watcher is a plugin**, the third on the Plugins page (`#/plugins`, after Wyze and eufy), with the same switch, **off by default**. Its entry has one sentence of what it does and an **Open** button to `#/sky`; it has no account, sign-in or sync, so no page of its own under `#/plugins/`. The page learns which plugins are on from `GET plugins` (`store.js`: `loadPlugins` at start-up, `setPlugins` whenever the Plugins page reads the list, `pluginOn('sky')`):

| | Plugin off | Plugin on |
|---|---|---|
| Left menu and phone tab bar | no **Sky Watcher** item | the item, right after Notifications, all the time (not only once a camera has it on) |
| A camera's page | no Sky Watcher card | the card, after the AI descriptions card, on every camera |
| `#/sky` | "Sky Watcher is off", with a button to Plugins; nothing is asked of the bridge | the Setup panel at the top, then the log; with no camera on yet, "Turn on Sky Watcher in a camera's settings" with a link to each camera's page (or to add one) |
| `PATCH cameras/:id {skyDetector: {enabled: true}}` | 400, field `plugins.sky`, "Turn on Sky Watcher in Plugins first." (the card shows it with a link to Plugins) | as before |

Switching it off keeps every camera's saved settings, so switching it on again brings the same cameras back. A switch changed in another browser shows here the next time the page is loaded or the Plugins page is opened (the bridge sends no event for plugins).

The explained entries are never built until their group is opened, so a night with hundreds of satellites stays quick. A correction changes the page in place (the entry stays where it is, and the counts and the strip follow it); nothing is loaded again.

## Run it on a Mac

```
cd Packages/CameraBridgeKit
swift run camerabridged --dev --data-dir /tmp/cb-dev --fake-discovery
open http://127.0.0.1:8080
```

`--dev` keeps the engine on loopback with nothing advertised and the HomeKit ports from 38100, so it never disturbs the Camera Bridge
app. The Add Camera page can add the demo camera (a test pattern with motion every minute) and `--fake-discovery` shows three
sample cameras on documentation addresses. `--preview` serves the engine's fixed sample data instead (no camera runs).
`camerabridged` finds this directory itself when started from the repository (`--static-dir` overrides).

The image installs these files in `/usr/share/camera-bridge/web`.

## Tests and tools

`linux/web-tests/` holds the tests of the pure modules (Node 22 or later, no packages): from the repository root, `node --test 'linux/web-tests/*.test.mjs'` (the quotes matter). `linux/web-dev/` holds the development tools:

| File | What |
|---|---|
| `dev-archive-server.mjs` | A Node server that serves `linux/web` and answers the recording routes from fixture files, with the daemon's Content-Security-Policy; switches for the cases "no folder", "drive missing", "disk full" and "stalled" |
| `make-fixtures.sh` | Builds the fixture files with ffmpeg |
| `conformance.mjs <base-url>` | Signs in and checks the shape of every recording route against a dev server, a daemon on a Mac or a box (the password comes from the environment and is never printed) |
| `lint.mjs` | Rejects what the Content-Security-Policy forbids: `innerHTML`, `style="…"`, `eval`, `fetch` outside `api.js` and the like |
| `soak/` | The Node side of the soak and fault tests: scripted clients, the sampler, the analyzer and the file verifier (`Tools/nvr-soak/README.md` says how a run goes) |

Both directories live outside `linux/web/` because the image copies that whole directory (`linux/os/build-image.sh`).

`linux/web-dev/README.md` describes the dev server's nine fake cameras and its scenarios, and `linux/web-tests/README.md` the tests; `sh linux/web-tests/run.sh` runs all of them and makes the fixture clips first (tests that need `ffmpeg` skip, with the reason, when it is missing).

Test recordings the way the box shows them. A page from `http://127.0.0.1` is a secure context, so browsers offer features there that they do not offer on `http://camera-bridge.local`, which is not one: print `window.isSecureContext` and `typeof VideoDecoder` to see the difference. To see what the box shows without opening your Mac to the network, give the loopback address a name that is not a secure context. Start the daemon for that name, and map the name to 127.0.0.1 inside one browser only (Chrome: `--host-resolver-rules="MAP nvr.test 127.0.0.1"`, with its own `--user-data-dir`):

```
cd Packages/CameraBridgeKit
swift run camerabridged --dev --data-dir /tmp/cb-nvr --port 8081 --fake-discovery --allowed-host nvr.test
```

Then open `http://nvr.test:8081` in that Chrome. `--dev` keeps the web interface on 127.0.0.1, so only this Mac can reach it, and the daemon advertises nothing and uses HomeKit ports from 38100, so it does not disturb the Camera Bridge app.

## Screenshots

`docs/screenshots/os/`: the page on a real box with real cameras, in the dark appearance; its README says what each picture shows, how they are taken, and that each keeps its name so a website can link to it.

Notifications (2026-10-22): a notice is not a banner any more. `js/notifications.js` shows each new one once as a toast at the top right (6 s, a warning 10 s, held by the pointer or the keyboard focus, at most 3, a swipe or the close button puts it away) after asking the bridge (`POST notifications/shown`: the bridge hands each to one browser, so nothing comes back on a reload and the phone and the Mac agree; nothing is kept in the browser; a wall display asks for none, so they stay for the owner's other devices), and counts the unread ones for the menu's bell. `js/screens/notifications.js` is the Notifications page (`#/notifications`: the bridge's log, a filter by section, "Mark all as read"; opening it marks what it shows as read). A notice whose action is `dismiss` (2026-10-31: the damaged configuration's, "Settings Restored From a Backup" or "Settings Could Not Be Read") stays until it is put away: its toast and its line on the page have Dismiss (`POST notifications/dismiss {id}` with the notice's id; a refusal is said in the bridge's words), on the page only while it is one of the bridge's notices (`store.notices`), and the line stays in the log. `js/screens/banners.js` keeps only the bridge's own state (paused, starting, not running) as a slim line.
